# Largest-win review packing failure modes

Written before the socket regression and before any production change for stopped exact_statistics-008.

1. A schema-valid writer can explicitly cite the complete comparison calculation, provide both score and margin, and ask two valid follow-ups, yet reviewer preparation can raise before transport. Replaying the same writer after generic feedback must not hide this failure. Capture and rethrow the actual payload/model exception and retain both raw writer attempts.
2. Claim packing can retain the winning game while dropping some of the complete winning-game comparison population. Independently derive all winning games, every tied maximum, each score and margin from the source archive. Verify every native calculation reference and each transmitted reconstructed immutable claim/source.
3. A calculation explicitly cited by the writer can disappear from the reviewer packet, or its source list can be shortened. Complete cited evidence and every immutable claim must reconstruct exactly. Optional whole uncited evidence may be omitted; cited evidence cannot.
4. Fixing capacity by raising the 8000 input or 6000 evidence cap, removing the strict schema, skipping independent review, dropping requested facts or suggestions, or accepting llm_validated=false would conceal the defect. Keep caps, schema validation, reviewed exact wording and both suggestions.
5. Tied maxima can lose one score/margin pair or one selected game during packing. Use a portable archive derived before loading, with two explicit maxima and all original winning games; verify both tied populations.
6. A reviewer that correctly rejects deliberately false margin wording must still fail closed. The scripted reviewer marks the offending span unsupported; neither a successful HTTP response nor a canonical fallback is a validated answer.
7. Replay can invoke another model or spend twice. Repeat the exact public HTTP request against isolated Redis; require identical committed output, no additional calls and unchanged synthetic budget.

The approved archive positive case uses exactly the stopped 555/556 answer text, two follow-ups and explicit native calculation citation, independently confirming NYK 120–BKN 66, 54 points, 69 compared wins. Portable fixtures derive text and IDs from their own source rather than pretending to contain those values. The synthetic archive has many equal maxima, so the portable positive fixture raises one winning final by one point; the tie case raises two, also updating their scoring events and one player free throw so the bundle reconciles. Each derived bundle has its own SHA and recorded adjustments. No production source or live provider is involved.

8. A repair narrowly fitting the stopped short answer can still reject coherent longer factual wording and longer supported follow-ups. Retain a roughly 600-byte answer that states source-backed score, margin, selected game, comparison population, phase coverage and archive limitations, with two complete related questions.
9. Highest- and lowest-scoring selections compare all 101 archived games rather than only wins. Explicit calculation citations must preserve that complete population, the selected score, all ties and lossless reviewer reconstruction under unchanged caps. These adjacent public HTTP regressions are authored before production changes.

10. Hoisting duplicated reviewer reference domains into shared schema definitions must not admit unknown claim/evidence IDs, out-of-range or wrong-type sealed span/follow-up indices, unsealed text, null required fields or additional properties. Every actual socket review response is validated unchanged, then independent mutated copies must be rejected by that same transmitted schema. These are assertions over actual E2E wires, not isolated implementation tests.

11. Before implementing ordinal support references, preserve the original six-case source snapshot and add actual-review-schema rejection probes for each support array in both assertion and follow-up collections: negative and out-of-range integers, booleans, fractions and null elements. In particular JSON true must never be accepted as integer index 1. Keep the existing unknown string-ID probes, valid raw reviewer response, exact native reference restoration and deliberate false-margin rejection. Run the highest-score socket control against the pre-ordinal implementation to establish that these rejection requirements precede the codec change.

12. Before the receipt-reference packing change: a tied answer may require two complete receipts with repeated native score statements and the same ordered comparison population. A lossless reference must restore every source ID in its original order, including the selected game moved first; sorting or dropping a reference changes provenance. Use a reference only after exact equality with the original list and only when it saves bytes including its annotation.
13. Before that change: arbitrary JSON evidence text/metadata can resemble a reference object. New reference fields belong to the wire evidence row, whose native schema forbids these fields, rather than interpreting arbitrary source JSON as an instruction. Restore native text before its existing canonical-JSON metadata reconstruction.
14. Before that change: compressing repeated citation IDs can accidentally reinterpret a prefix suffix, an omitted source, or a different evidence row order. Keep full strings for absent rows and already prefixed claim references; only transmitted full IDs receive row ordinals. Restore exact IDs before native validation and preserve every explicit proposed citation. Candidate packing must copy claim rows/context so a rejected candidate cannot alter the previously accepted packet.
