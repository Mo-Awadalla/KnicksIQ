# Complete archive source unit failure modes

Written before the HTTP specification and implementation. The unchanged scorer
takes five actual ranked documents and then unions verified source mappings.
The retained corpus has no complete multi-game result or player-identity unit.

- A supposed aggregate lists nine source IDs but omits their facts. Every
  represented game must have its exact date, NBA identity, phase, teams, final
  score and result in the retained text and structured rows.
- A representative game ID disguises a multi-game document. Multi-game units
  have no scalar game ID; their population is explicit and complete.
- Evaluation IDs, questions or target sets influence unit construction or
  ranking. Build opponent result units for every available opponent from
  release-scoped final SQL games, using the same recipe for all groups.
- A narrow game/date/phase/player/period request retrieves an aggregate that
  includes out-of-scope facts. Require its complete population to fit the
  selected scope; result units do not support period or player-stat filters.
- Fusion deduplicates all game-less documents as one game. Unit identity must
  include its stable content digest and type, independent of ranking source.
- A foreign release, altered structured row, invented canonical source, changed
  player alias, or mismatched text reaches tools. Revalidate against current
  canonical SQL rows and recipe before accepting a unit.
- Canonical player identity is confused with game performance or an anchor.
  Identity units can support entity discovery, never choose a missing game or
  verify a client narrative. Alias provenance must distinguish approved roster
  fields from the project's curated alias policy.
- Index construction and local retrieval produce different unit identities or
  omit units from offline artifacts. Use one deterministic recipe, retain the
  content, and keep new immutable candidate indexing separate from old proofs.
- Existing candidate collections are modified to force reuse. Conflicting new
  content must fail preflight; use a fresh explicit index revision for any write.
- Receipt identity checks are called source relevance or gold approval. The
  independent test checks actual retained facts before constructing mappings;
  relevance adjudication and owner approval remain separate release gates.
- A failed check overwrites evidence or performs paid/provider/dense calls.
  Retain fresh-directory HTTP/index/mapping receipts and deny paid dispatch.
- The same source identity carries different query-dependent rank fields inside
  the source receipt, so an independently verified mapping cannot be reused.
  Keep actual ranks in the search capture, and immutable source facts in Evidence.
