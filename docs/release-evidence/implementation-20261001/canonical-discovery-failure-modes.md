# Bounded canonical discovery failure modes

Written before HTTP checks and runtime changes. Discovery searches actual
release-scoped SQL records before clarification or model admission. It does not
resolve an absent game reference, approve relevance, change immutable gold, or
earn retrieval credit just because the answer clarifies.

- Clarification returns before any search, leaving the 50 semantic members
  without genuine candidate/ranked captures. Capture real search output, including
  an empty result; never invent returned IDs or substitute gold target sets.
- A preflight invokes a model, dense embedding, hosted vector service, retry or
  budget reservation. It must use bounded local lexical retrieval only, even
  when paid/dense features are enabled for later investigation.
- A curated player alias cannot search the independently resolved canonical
  name. Query expansion may use resolved player names or opponent IDs from
  ordinary request parsing, never evaluation IDs, labels or expected targets.
- Candidate evidence chooses a game for an unanchored pronoun, replaces the
  last-ten-message rule, becomes an authoritative statistic or removes required
  measure clarification. Scope and clarification stay unchanged by retrieval.
- Wrong-release, opponent, date, phase or player documents pass filters, or an
  empty selected population accidentally becomes an unfiltered archive query.
- Ranked receipt order differs from the returned search order; more than five
  ranked or twenty candidate receipts are reported; queries or filters are
  absent from private captures. Retain actual evidence and release bindings.
- SQL failures/timeouts are reported as successful retrieval. Record dependency
  failure with empty ranked/candidate lists. Do not dispatch a paid model after
  failed preflight; preserve necessary clarification and visible degradation.
- A replay repeats discovery, a changed transcript is accepted, or cancellation
  leaves a turn lock/reservation that prevents safe exact retry. Verify real HTTP
  replay, conflict, cancellation and unchanged local budget state.

Verification uses original immutable questions through HTTP against the approved
bundle, real SQL and disposable Redis. Full-cohort observations are an engineering
probe; they are not an approved release evaluation or Recall@5 measurement.
