# Confirmed release implementation: failure modes and verification order

Written before implementation or new checks. Authority is the confirmed handoff
at `/private/tmp/knicksiq-release-implementation-handoff.md`, whose bytes are bound
in the implementation register. The September 30 release package remains sealed.

The first implementation is a network-free canonical review command. Its end to
end checks invoke the command as a separate process against the actual retained
package, repeat it into a new directory, compare artifacts, and retain every
receipt. They are written before the command. No new unit tests are planned.

Failures the review command must prevent:

- A changed bundle, question, baseline record, package reference or checksum
  passes as the retained release. Verify bytes before deriving expectations.
- A different or incomplete question population, changed context, or changed
  semantic membership passes as the original 120 questions and 50 members.
- The previous all-43-clarify proposal overrides the confirmed Boston and tie
  decisions. Recompute the complete archive, keep all ties, describe both Boston
  maximum unanswered runs, and retain the old proposals as history.
- A Knicks free throw fails to terminate a Boston run, a quarter break or
  zero-point event terminates one, event order changes, or corrected cumulative
  scores certify an unsupported run. Use canonical sequence and reject score
  ambiguity. Retain event IDs, clocks, before/after scores and row hashes.
- An undefined measure is silently given a default, or a follow-up's assistant
  assertion becomes committed state. Preserve contexts and request the approved
  game/event/measure inputs explicitly.
- Canonical player identity or a resolver alias is misrepresented as evidence
  about an unspecified game. Investigate the actual player row and indexed
  document inventory; reject unsupported relevance rather than create gold.
- The settled seven target sets (including nine Atlanta game targets) change to
  improve Recall@5. Preserve them verbatim and check each canonical source.
- A source-count calculation is presented as measured recall, or integrity is
  presented as semantic relevance. Distinguish candidate support, independently
  settled targets, actual rankings, and the conditional one-source bound.
- An audit creates approval, freezes an incomplete contract, writes a fabricated
  ranked receipt, calls a provider, reserves budget, reads credentials, modifies
  production, or overwrites an earlier attempt. No such path is available.
- A failed audit erases its evidence. Keep a structured failure receipt; refuse
  an existing output directory. Repeated successful audit bytes must match.

Before the subsequent runtime implementation, write HTTP E2E checks for these
additional failures (these stages remain dependent on semantic closure):

- Clarification discovery accidentally dispatches a completion, paid embedding,
  reranker or planner, creates a reservation, or commits retrieved examples as
  verified narrative state; refuses and exact replay must remain zero-call.
- Wrong release/scope documents or aggregates bypass filters, acquire a fake
  representative game ID, or map to canonical rows absent from their contents.
- Retrieval capture contains invented order/candidates, misses a timeout,
  truncates before aggregating correctly, or exposes internal capture publicly.
- All tied game stories or Boston maxima are silently truncated by answer,
  evidence or tool-round bounds; causal language appears without causal support.
- Admission accepts a different route, key, model, tokenizer, environment,
  dataset, current month, unknown capacity, or unknown price. Reserve original
  load/recovery demand before evaluation within the unchanged cumulative caps.
- Retry, cancellation, crash, settlement error, or rollback releases unknown
  spend or resets incurred usage. Journal requests before dispatch and require
  exact receipt attribution and audited continuation. Do not reopen the original
  stopped smoke journal without its missing inventory.
- A shadow percentage substitutes for actual deterministic sample membership;
  the distinct 120-turn shadow cohort, call ceiling and all original workloads
  and readiness thresholds must remain unchanged.

Hard stops are evidence conditions, not implementation approval requests. If
independent identity relevance fails, retain the incompatibility dossier and
stop semantic closure. If admission fails, issue no paid requests. Production
launch still needs passing readiness and owner approval bound to the completed
record digest, exact targets and rollback.
