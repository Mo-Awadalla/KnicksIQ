Privacy

KnicksIQ has no accounts, advertising scripts, or application cookies. Please do not put sensitive personal information in chat.

This browser tab

This tab saves your draft, an opaque access capability, and any pending message or retry command in sessionStorage under knicksiq-chat-v1. Refresh uses that capability to retrieve the saved conversation from the server. We do not maintain a browser history sidebar or personal profile. Your browser controls the lifetime of tab storage. A separate tab starts independently; some browser duplication and session-restore features can copy tab storage.

New chat clears this tab’s current application copy and tries to stop an old reply. It does not delete server records or provider copies. A lost or expired capability cannot recover an old conversation. Do not share your tab storage.

Server records

The API retains conversation messages, reply prefixes, completed replies, request outcomes, revisions, and private factual context in Redis. Records expire 24 hours after their last conversation write. Sending, retrying, saving a reply prefix, finishing, stopping, or reconciling an abandoned reply renews that period. Simply reading a conversation does not renew it. New chat abandons access to the old record; there is no public deletion endpoint.

Abuse controls use secret-keyed hashes of the connecting IP address and current UTC day. Application counters do not retain the raw IP address. Bounded fallback counters can remain in process memory until cleanup or process exit.

Model and search providers

The API sends your message, bounded conversation history, and necessary private factual context to a configured model provider through an inference gateway, currently OpenRouter. It does not send your browser’s IP address, cookies, HTTP headers, or chat capability in that model payload. Gateway and provider policies govern their copies; we cannot promise their retention period. There is no automatic paid regeneration on refresh or connection recovery. Retry explicitly starts another attempt.

When configured factual search uses Qdrant Cloud inference, a search query derived from your message can be sent there for embedding. Local embedding does not send that text to Qdrant for embedding. Provider retention policies apply.

Diagnostics and connection information

The application records bounded operational outcomes and usage summaries, not intentional raw questions, capabilities, evidence, or provider payloads. When browser Sentry monitoring is configured, outgoing error events are reduced to an event identifier, timestamp, fixed error type, and redacted text. Browser request details, breadcrumbs, exception messages, stack frames, and conversation state are omitted. Browser session replay and performance tracing are disabled. Hosting and network providers receive connection information needed to deliver requests; their logging and retention are outside these application controls.

Fonts and feedback

Fonts are served by KnicksIQ, not a third-party font service. Feedback is submitted only when you choose to send the separate form. Formspree receives those fields under its own retention policies. A reply email is optional and requires consent.
